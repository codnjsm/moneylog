# 회고 — 주식거래 수익률(%) 표시

## 계획과 실제
핵심 기능(수익률 계산·표시·매수가 0원 처리)은 계획대로 잘 됐다. 다만 실행 중 실시간으로 색상 정책이 바뀌었고(income/expense → 빨강/파랑), 그 결과 적대적 리뷰에서 "금액과 수익률 색상이 같은 줄에서 충돌한다"는 major 버그가 발견됐다. 검증(validation)도 계획에 없었는데, 리뷰에서 buyPrice/quantity에 음수·0을 막는 장치가 실제로 없다는 게 드러났다.

## 배운 것
- **새 색상 규칙을 도입할 때는 인접 요소의 기존 색상 의미와 충돌하는지 반드시 확인해야 한다.** 이번엔 수익률만 보고 "괜찮다"고 판단했는데, 바로 옆 금액 색상과 부딪히는 걸 놓쳤다. 적대적 리뷰가 아니었으면 배포됐을 수 있는 버그.
- **`<input min={0}>`는 실제 검증이 아니다.** `<form>`으로 감싸지 않고 버튼 `onClick`으로 저장하는 구조에서는 브라우저의 constraint validation이 전혀 작동하지 않는다. 값 검증은 JS 레벨(`valid` 계산)에서 직접 해야 한다 — 이 프로젝트의 다른 모달들도 같은 구조라 비슷한 문제가 있을 수 있다.
- **적대적 리뷰(6개 관점 병렬)가 실제로 값어치가 있었다.** 사람이 직접 브라우저로 확인한 것(양수/0원 케이스)은 다 정상이었지만, 코드를 라인 단위로 파고든 리뷰가 사람이 테스트 안 해본 조합(음수 입력, 무손익, 매우 작은 매수가)에서 실재하는 문제를 여러 개 찾아냈다.
