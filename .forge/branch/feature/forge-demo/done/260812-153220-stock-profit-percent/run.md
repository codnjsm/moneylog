# 실행 기록 — 주식거래 수익률(%) 표시

계획대로 규모가 작아 별도 워크플로우 없이 직접 구현했다. 계획과 실제가 거의 일치했다.

- S1. 수익률 계산 로직 추가 — ✅ 계획대로 (`StockTab.tsx`, `StockTradeModal.tsx` 각각에 로컬 함수로 추가, 매수가 0이면 null)
- S2. `StockTab.tsx` 카드에 표시 — ✅ 계획대로 (금액 옆에 작은 글씨로 `(+8.5%)` / `(—)`)
- S3. `StockTradeModal.tsx` 예상 수익에 표시 — ✅ 계획대로
- S4. 검증 — ✅ `tsc -b`, `npm run lint`(기존에 알려진 4개 문제만 남고 신규 없음), `npm run build` 모두 통과. 브라우저에서 매수가>0(스크린샷으로 확인)/매수가=0(사용자 확인, "—" 표시됨) 두 케이스 모두 확인됨.

## 계획과 다르게 실행 중 바뀐 것 (divergence)
- **색상 — 계획에서 벗어남**: 그릴링 때는 "기존 income/expense 클래스 재사용"으로 정했었는데, 실제 화면을 보고 사용자가 "주식은 상승=빨강, 하락=파랑이 익숙하다"고 요청해서 `--danger`(빨강, 상승)/`--accent`(파랑, 하락) 전용 색상으로 바꿈. income/expense(초록/빨강)와는 다른 배색이라 계획과 다르지만, 실제 사용해보고 나온 합리적인 조정이라 반영함.
- **CSS 추가 — 계획에 없던 것**: `.expense-amount`에 `display:flex; align-items:center; gap:4px`를 추가해서 금액과 수익률 사이 정렬/간격을 맞춤. 이 클래스는 다른 탭에서도 쓰이지만 텍스트만 들어있어서 시각적 영향 없음.

## 참고
- 별도 CSS 클래스를 새로 만들지 않고, 이미 파일에 있던 인라인 스타일 관례(`style={{fontWeight:700}}` 등)를 그대로 따랐다.
- 두 파일에 계산 로직이 거의 동일하게 중복되지만, 원래 `profitOf`도 두 파일에 각각 따로 있던 기존 관례를 그대로 따른 것 — 새로운 결정 아님.
