# 적대적 리뷰 — 주식거래 수익률(%) 표시

**요약**: 6개 관점 병렬 탐지 → 15개 finding → 반박 검증 통과 12개(major 6, minor 6). 대부분 하나의 핵심 문제(A)로 귀결됨.

## A. [major] 금액 색상(초록/빨강)과 수익률 색상(빨강/파랑)이 같은 줄에서 충돌
여러 관점(실패지점·숨은가정·요구사항오독·예상못한오용·근거약한결정)이 독립적으로 같은 문제를 발견함.

- 금액: `profit<0 ? 'expense'(빨강) : 'income'(초록)`
- 수익률: `percent<0 ? '--accent'(파랑) : '--danger'(빨강)`
- 매수가>0·수량>0인 **정상 케이스에서 항상 같은 부호**를 가지므로: **이익일 때 금액은 초록인데 바로 옆 수익률은 빨강(danger, 앱 전역에서 "손실/삭제" 의미로 쓰는 색)**, **손실일 때 금액은 빨강인데 수익률은 파랑**으로 표시됨. 극단적 edge case가 아니라 매 거래마다 발생.

## B. [major] buyPrice 음수 / quantity 0·음수를 막는 검증이 실제로 없음
`<input type="number" min={0}>`는 `<form>`이 없어서 브라우저 제약검증이 전혀 안 걸리고(버튼이 그냥 `onClick`), `valid` 체크도 문자열 truthy 검사뿐이라 `-100`, `0` 같은 값도 그대로 저장됨. 이런 값이 들어가면 수익률 부호가 실제 손익과 반대로 표시될 수 있음(예: buyPrice=-100, sellPrice=50 → 이익인데 수익률은 음수로 표시).

## C. [minor] 매도가=매수가(무손익)일 때 "+0.0%"가 빨강으로 표시됨
손익이 0인데 수익률에 '+' 기호와 danger(빨강) 색이 붙어서 이익이 난 것처럼 보임.

## D. [minor] buyPrice가 매우 작을 때 수익률 문자열이 길어져 카드가 넘칠 수 있음
예: buyPrice=1원, sellPrice=100000원 → `(+9999900.0%)` 같은 긴 문자열.

## E. [minor] 계획 범위 밖 — 공유 CSS 클래스(`.expense-amount`) 변경이 ExpenseTab에도 영향
실제 회귀 위험은 낮음(ExpenseTab 사용처는 텍스트만 있어서 시각적 차이 거의 없음)이나 계획서에 명시 안 된 변경.

## F. [minor] 계산·포맷·색상 로직이 StockTab.tsx / StockTradeModal.tsx에 그대로 중복됨
공용 유틸로 뺄 수 있었는데 안 뺌 — 유지보수 시 한쪽만 고칠 위험.

## 처리 방향 (사용자 결정 대기)
A/B/C는 실제 사용자에게 잘못된 신호를 주는 진짜 버그라 고치는 걸 추천. D/E/F는 지금 규모에서 급하지 않음.
